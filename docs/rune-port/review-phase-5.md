**Still open / not verified:**
- **Real hardware.** Everything above uses virtual ports and synthetic clocks. Still needed: the real MPK mini Play mk3, sleep / wake, felt latency, Linux (ALSA) and Windows.
- **Linux and Windows hot-plug.** They have no notifications here. Hot-plug is polling only (≤ 500 ms), and a port replaced under the same id between two polls is not detected. On ALSA a new port normally gets a new client id.
- **Same-id replacement on CoreMIDI.** In the runs here, CoreMIDI gave the replacement source a new id, so the reconnect went through name recovery. The "same id, list unchanged" path, which reconnects through the removed-source counter, is implemented but was not hit.
- **Lock hold measurements** are from a debug build on this Mac, with no release-build run. The max per-message figure includes preemption when the suite runs in parallel.
- **App wiring.** Calling `ProfileSaves::apply`, the waker, `poll` and `enable_with_settings` from the app loop is phase 7, as is the split-point control (or phase 9 with the controller dialog).
