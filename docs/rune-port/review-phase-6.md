"Before" figures are the reviewers' probes on 536b274, or the same probe re-run on 536b274 by
this fix (in a scratch worktree, since removed). "After" figures come from the tests named in
the table (debug build, this Mac). Test files are under `rune/crates/mdaw-packs/tests/` unless
noted.

After the fixes:
- `cargo test --workspace`: 1,110 passed, 0 failed, 22 ignored. `cargo clippy --workspace
  --all-targets -- -D warnings` and `cargo fmt --all --check` are clean.
- The live test (`cargo test -p mdaw-packs --test live -- --ignored`, real catalog + GitHub
  over TLS, with the lock and fsync in place): 30 / 30 files byte-identical to Electron's, each
  app lists and verifies the other's install; Rust install 30 files in 3.4 s.
- `npm test`: 899 passed (75 files). `npm run typecheck` is clean; `npm run lint` has 0 errors.
- Stability: `cargo test -p mdaw-packs` 20 / 20 sequential runs, and 8 / 8 runs with two packs
  suites and an engine suite running at the same time (that load exposed a second timing flake,
  `l_e_pause_all…`, fixed below; before that fix 3 of 6 loaded rounds failed).
- **Goldens.** `packs_io.json` and every engine / parity fixture are identical.
  `packs_validate.json` changed on purpose (finding 11): regenerated from the fixed TS,
  308 → 313 manifests (5 Unicode cases), identical in Rust. With the Rust NFC change reverted
  the golden fails, so it pins the fix.

Several findings were Electron bugs: **Electron bug fixed in both apps (user decision
2026-11-18)**. The packs-folder rules both apps now share are written down in
[packs-dir-protocol.md](packs-dir-protocol.md).

**Public API changes (`mdaw-packs`, all additive)** — for the Phase 7 UI:
- `mdaw_packs::lock` (new): `DirLock`, `LockGuard`, `LockError`, `LOCK_DIR`, `STALE_PREFIX`,
  `HEARTBEAT`, `STALE_AFTER`, `RETRY`, `pid_alive`.
- `installer`: `InstallerOptions.uninstall_lock_wait`, `UNINSTALL_LOCK_WAIT`,
  `PACKS_BUSY_MESSAGE`, `INTERNAL_ERROR_MESSAGE`, `is_complete_install`,
  `PackInstaller::dir_lock`. `FsOp::Sync` and `FsOp::Remove` (the enum is not
  `#[non_exhaustive]`: an exhaustive external match would need the new arms; test-only type).
- `store`: `PackStore::queued_installs`; `PackStore::cancel` now returns true for a queued
  request. `Signal::same`.
- `http`: `tcp_connect` (now public), `resolve`, `TlsConnector::with_roots`,
  `HAPPY_EYEBALLS_DELAY`, `MAX_LINE`, `MAX_TRAILER_BYTES`, `MAX_TRAILER_LINES`, `MAX_INTERIM`,
  `Display + Error for HttpError`, `#[doc(hidden)] Response::buffered_capacity`.
- `mdaw_engine::engine::preview::PREVIEW_RETIRE`.
- Behaviour: `read_installed_meta` / `is_installed` return none / false for a symlinked folder.

**Still open / not verified:**
- **Power loss** on real hardware (the fsync order is tested by recording it).
- **Windows**: connect falls back to sequential `connect_timeout` under the shared deadline
  (not cancellable mid-attempt); the lock uses the mtime rule only; directory fsync is skipped.
  Nothing was run on Windows or Linux.
- **DNS** is not interruptible at the OS level; the request returns at once, the lookup thread
  finishes in the background. No slow-DNS test.
- **`br` / `zstd`** responses fail instead of being decoded (Node decodes them); GitHub raw
  serves identity when asked.
- **1xx**: up to 8 interim responses are skipped; undici fails on any.
- An install waiting for the lock emits no extra state (the card stays at its optimistic
  `downloading` 0 B), as the protocol allows.
- The test TLS CA and localhost key under `tests/fixtures/tls/` are test-only material.
