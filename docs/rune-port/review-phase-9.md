"Before" is the behaviour on e184ece (the reviewers' probes, or what the new test asserts against
the old code path); "after" comes from the tests named in the table. Paths are under
`rune/crates/mdaw-app/src/` unless noted. Most new tests are in `tests/t_p9_review.rs`.

After the fixes:
- `cargo test --workspace --no-fail-fast`: **1,346 passed, 0 failed, 25 ignored** (34 test
  binaries). `cargo clippy --workspace --all-targets -- -D warnings` and `cargo fmt --all --check`
  are clean. (One run showed 2 `mdaw-model` failures: the Phase 10 worktree rebuilt that crate into
  the shared `rune/target` mid-run; after touching the sources again the crate passes 426 / 426 and
  the full run above is clean.)
- `npm test`: **923 passed** (916 at e184ece + 7 new); `tsc --noEmit` clean.
- DSP fixtures recaptured: `rune/parity/fixtures/sample_processor.json` (44.1 kHz context, one new
  case) and the new `sample_processor_48k.json` (`UI_SNAP_CONTEXT_RATE=48000`).
- Rune screenshots recaptured into `docs/parity/phase-9/` from a private copy of the binary and
  every pair inspected (half-scale montages Electron | Rune before | Rune after, plus a before→after
  pixel diff). Changed: `samples-empty`, `samples-generate`, `samples-process`, `settings`
  (slider ranges + thumbs; the top bar no longer shows "Muted" on the Generate tab) and
  `palette-search` (rows now the same as Electron's). The TS changes don't alter any captured
  state, so the Electron shots were kept.

Electron bugs fixed in both apps (user decision 2026-11-18): findings 5, 6 and 14 (below).

**Still open / not fixed:**
- The Packs detail panel rows (~9 pt) and the Settings Credits block (~8 pt) still sit higher than
  Electron's; the palette list 4–8 pt higher (heading spacing).
- `FileLoader::load_file` (pad `{ kind: 'file' }` sources) still decodes without registering in the
  sample store (pads have their own cache entry, which `invalidate_pack_buffers` drops); only the
  sample manager's samples reload in place.
- Loads of a path being reloaded don't wait for the reload (`whenReloaded`), and the waveform timings
  were measured in a debug build only.
- The pack reinstall test uses a local pack folder re-listed by the service, not a network install;
  VoiceOver was not run against the new dialog names.
